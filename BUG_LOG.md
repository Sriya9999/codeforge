# Bug Fix Log — Grading Console

Bugs were **reproduced against the original prototype** (`original/index.html`, kept verbatim)
by `tests/reproduce-original.mjs`. That script runs the prototype in headless Chromium with the exact
SheetJS build its unpinned CDN URL resolves to (0.18.5). The evidence quoted in the tables is that script's
output. Rows marked *(from source)* are substantiated by reading the code rather than isolated in that run,
and I say which. Each fix is covered by `tests/core.test.mjs` (20 unit tests) and/or `tests/e2e.test.mjs`
(8 browser flows) against the rebuilt console.

Severity: **Critical** = wrong or missing grades in the exported file · **High** = wrong numbers shown, or a
workflow that breaks · **Medium** = misleading or confusing · **Low** = polish or robustness.

---

## A. Wrong grades in the exported file (Critical)

| # | Bug / Issue | How I reproduced it | Root cause | Fix implemented | How I tested the fix |
|---|---|---|---|---|---|
| 1 | **Every BITS ID in the export is `undefined`** | Uploaded a file with the brief's header `Student’s BITS ID`, selected a course, exported. Every row read `undefined,77,A-` | The export read `d["BITS ID"]`. `sheet_to_json` keys each row by the literal header text, so the key is `Student’s BITS ID` (with a curly apostrophe). The prototype's own guidance also named the column "BITS ID", so the input spec and the code disagreed | Columns are found by a normalised header match (`normaliseHeader`): case, spacing and apostrophe style are ignored, and column order doesn't matter. A missing column is a hard, explained error | Unit: "header detection tolerates apostrophe style…" and "column order…". E2E happy path asserts all 120 rows match `^2024A7PS\d{4}P,\d+,Grade$` |
| 2 | **Students silently dropped when ranges don't cover 0–100** | Changed A's max to 90. No error was shown, Download stayed enabled, and the CSV held **48 of 50** students. Setting E's min to 5 also passed validation | `validateRanges()` only compared each band with its neighbour (`max === prevMin-1`). It never checked that A reaches 100 or that E starts at 0. The export loop `for…break` then skipped any student who matched no band, without a word | `validateBands()` walks every whole mark from 0 to 100 and reports each gap, overlap, reversed bound, out-of-range bound and inverted order in a specific sentence. `buildCsv()` also **throws** if any student would get no grade, so export can never drop a student silently | Unit: "band validation explains gaps…", "CSV export refuses…". E2E: A max 90 gives "No grade covers marks 91–100 (top of the scale)" and the export button stays disabled |
| 3 | **Blank, non-numeric, negative, >100 and decimal marks silently dropped** | `edge-cases.xlsx`: 14 "Course A" rows, only **8** exported. `-5`, `104`, `79.5`, blank and `"AB"` all vanished with no message | No validation of the marks at all. `79.5` falls between bands 70–79 and 80–100, so it matched nothing. Out-of-range and non-numeric values matched nothing either | `parseMark()` sorts every value into ok, text-number, decimal, blank, non-numeric or out-of-range. Rows with a problem go into **Records requiring attention** (shown with the Excel row number), are left out of the stats, and must be acknowledged before export. Decimals get an opt-in "Round half-up (79.5 → 80)" action, with each change listed and undoable | Unit: "every data-quality problem is flagged…", "decimal marks are rounded…". E2E edge-case flow checks each issue text, the rounding, the acknowledgement gate and the exact 6 exported rows |
| 4 | **Duplicate BITS IDs exported twice / conflicting marks both graded** | `edge-cases.xlsx`: ID `…0002P` with marks 71 and 64 came out as two rows with different grades. The exact duplicate `…0003P` also came out twice | No duplicate detection | Duplicates are grouped by course + ID. An exact repeat is counted once and noted. Conflicting marks hold back **both** rows, because the tool can't know which one is right. The same ID in *different* courses is allowed | Unit: conflicting pair is `attention, attention`, exact pair is `valid, duplicate`, and cross-course IDs are both valid. E2E export has 0003 once and 0002 not at all |
| 5 | **Rows with a blank BITS ID exported as `undefined`** | Row with an empty ID and mark 45 was exported as `undefined,45,C` | No required-field validation | A missing ID is flagged, so the row is never graded | Unit and E2E edge-case: "BITS ID is blank" appears in the attention table |
| 6 | **CSV corrupted by commas and quotes; formula injection** | Instructor `Rao, K. "Senior"` and course `Course, With "Comma"` spilled into extra columns. An ID of `=HYPERLINK(...)` was written raw, so Excel would run it as a formula | String interpolation with no RFC 4180 quoting. The original also wrote `Course, ${…}` with a stray leading space | `csvCell()` quotes fields that need it, doubles embedded quotes, and prefixes `= + - @ tab CR` values with `'` so they display as text. The layout still matches the original (`Instructor`, `Course`, blank line, `BITS ID,Total Marks,Grade`), with a UTF-8 BOM so Excel shows `’` correctly | Unit: exact expected CSV string. E2E: CSV-hostile file round-trips to the exact expected lines |

### What I prevented from happening again

- **One source of truth for grading rules.** Everything that decides a grade (`parseSheet`, `validateBands`,
  `gradeFor`, `buildCsv`) lives in `src/core.js`, which has no DOM code and is unit-tested in Node.
- **Fail closed at export.** `buildCsv` throws rather than write a file with a missing or ungraded student,
  even if some future UI bug enables the button.
- **No silent exclusion.** A row is either graded, counted once as an exact duplicate, or listed under
  *Records requiring attention* with its Excel row number and reason, and export requires acknowledging it.
- **Regression suite.** `npm test` runs 20 unit tests and 8 browser flows on the fixtures in `fixtures/`.
  These cover every scenario in the brief's "test beyond the happy path" list, plus a 20,000-row file.
